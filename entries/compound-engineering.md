# compound-engineering

Every's workflow plugin: 36 skills for a loop of brainstorm, plan, build, review, then write down what the change taught, so the next change can read it. It includes multi-persona code and document review, debugging, PR shepherding, and a hands-off `lfg` pipeline that runs the whole loop.

## Who it is for

Developers and teams who want a full engineering workflow in Grok, with written plans, reviews by several specialist personas, and a growing `docs/solutions/` record of what each fix taught. The skills are long and dispatch many subagents, so a review or a pipeline run spends real model time. Read the privacy note under "Why it is assayed" before running reviews in a repository whose code may not leave your host's provider.

## Install

```bash
grok plugin marketplace add HermeticOrmus/liquid-gold-grok
grok plugin install compound-engineering@liquid-gold-grok
```

Run `/ce-setup` once per repository for the health check and the optional `.compound-engineering/config.local.yaml`.

## Why it is assayed

Every gate passed at the pin, all 36 skills the README counts load, and the plugin runs nothing on its own: no hooks, no MCP server. The skills are written for Grok as well as Claude Code. They name Grok's own tools (`run_terminal_command`, `get_command_or_subagent_output`, `scheduler_create`) where a harness matters ([watch-loop.md:20](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-babysit-pr/references/watch-loop.md#L20)), and the vessel already carries gold from a Grok Build report: probe prompts reached the user as Grok question cards until [#1526](https://github.com/EveryInc/compound-engineering-plugin/pull/1526) made every skill pick the blocking-question tool by capability (K-01). A second seal is a privacy control: [#1396](https://github.com/EveryInc/compound-engineering-plugin/pull/1396) added a repo setting that keeps review content on the host (K-02).

One fracture keeps it from gold. `PRIVACY.md`, which the README links under "Reporting and data handling" ([README.md:446](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/README.md#L446)), says data leaves the machine only through the host or "an explicitly invoked integration", and "If you do not invoke these integrations, they do not transmit your project data" ([PRIVACY.md:26](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/PRIVACY.md#L26)). But `ce-code-review` and `ce-doc-review` run a cross-model pass by default (`cross_model_review_mode` defaults to `auto`): when the adversarial reviewer, or doc-review's judgment trio, is selected and an agent CLI from a different model family is on `PATH` (`codex`, `claude`, or `cursor-agent`), the diff or the full document goes to that provider. "Invoking this skill is itself the authorization" ([ce-code-review/SKILL.md:31](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-code-review/SKILL.md#L31)). In an interactive run the skill prints one notice line before sending; in `mode:agent`, which `lfg` uses, it prints nothing to the user and writes an audit line to stderr ([cross-model-review.md:85](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-code-review/references/cross-model-review.md#L85)). The per-skill guides disclose the pass and its off switch ([docs/guides/ce-code-review.md:131](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/docs/guides/ce-code-review.md#L131)), so under this library's rubric the contradiction is a fracture, not a break (K-03). At the pin, in a scratch repository, the doc-review worker called a stub `codex` CLI and logged "full document content egresses to this provider via this route" until `CROSS_MODEL_PEERS=none` stopped it. The workarounds below were run on the scripts, not in a Grok session, so the entry is assayed until they are.

## What it can execute

- **Hooks:** none.
- **MCP servers:** none. The bundled Context7 server was removed in [#486](https://github.com/EveryInc/compound-engineering-plugin/issues/486); researcher prompts use Context7 only when you have its MCP server connected or its `ctx7` CLI installed.
- **Scripts:** run by the agent when a skill says so, from each skill's `scripts/` folder:
  - Cross-model workers for `ce-code-review`, `ce-doc-review`, `ce-pov` and `ce-work`, started as detached jobs by `peer-job-runner.py`. They launch a read-only `codex`, `claude`, `grok`, `cursor-agent` or `opencode` process. Code and doc review run one by default (K-03); `ce-pov` runs a panel only on an explicit request, and `ce-work`'s external author is off unless `work_engine_mode` turns it on.
  - `elevation-dispatch.sh` for `ce-plan` and `ce-brainstorm` runs one step on a model you name through the `claude` CLI, with `--tools Read,Glob,Grep,WebSearch,WebFetch`. Nothing elevates unless you, a caller token or the config names a model.
  - `light-webserver.js` (brainstorm and prototype pages) and `live-endpoint.js` (`ce-polish` live mode) are local HTTP servers bound to `127.0.0.1` by default ([light-webserver.js:11](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-brainstorm/scripts/light-webserver.js#L11)).
  - `ce-compound`'s session-history scripts read Claude Code, Codex, Cursor, Pi and omp transcripts recorded for the repository inside a scan window of days ([discover-sessions.sh:47](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-compound/scripts/session-history/discover-sessions.sh#L47)); Full mode, the default, runs them automatically (K-05).
  - `packs-resolve.py` clones the git sources a repository's CE config lists under `packs:`, each at a required `ref`.
  - `ce-resolve-pr-feedback`, `ce-babysit-pr` and `ce-commit-push-pr` call `gh` and `git` to read, reply to and resolve review threads, rerun failed CI, commit and push. After `ce-commit-push-pr` opens a PR it hands off to `ce-babysit-pr` by default, which fixes, commits, pushes, replies and resolves without asking, up to a 3-day backstop, and never merges outside its `stack-land` posture ([ce-babysit-pr/SKILL.md:29](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-babysit-pr/SKILL.md#L29)). `babysit:off` or `auto_babysit: false` skips it ([ce-commit-push-pr/SKILL.md:69](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-commit-push-pr/SKILL.md#L69)).
  - `ce-setup`'s `check-health` reports missing tools and prints their install commands; it installs nothing.
- **Network:** the cross-model peers above (OpenAI through `codex`, Anthropic through `claude`, xAI through `grok`, Cursor through `cursor-agent`, OpenCode); GitHub through `gh`; git sources for packs; and, only when you ask for them, Proof at `proofeditor.ai` (`ce-proof`), the OpenAI API with your `OPENAI_API_KEY` for `ce-polish`'s voice interviewer ([live-endpoint.js:53](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-polish/scripts/live-endpoint.js#L53)), the Spiral CLI for `ce-promote`, and Slack, GitHub Issues and email for `ce-sweep`, which acknowledges items at their source. Researcher subagents use the agent's own web tools.
- **Writes:** `docs/solutions/` learnings, plans and brainstorms under the configured docs root, `.compound-engineering/` config, review run folders, a packs cache, and git worktrees for `ce-work`, `ce-optimize` and `ce-worktree`.
- **Disclosed in its README:** partly. The per-skill guides linked from the README describe the cross-model pass, the babysit handoff and the session-history probe, each with an opt-out ([configuration.md:98](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/docs/guides/configuration.md#L98), [ce-commit-push-pr.md:20](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/docs/guides/ce-commit-push-pr.md#L20), [ce-compound.md:95](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/docs/guides/ce-compound.md#L95)); `PRIVACY.md` leaves out the default cross-model pass (K-03) and lists a Context7 server the plugin no longer ships (K-04).

## Workarounds

- **K-03, per repository:** add `cross_model_review_mode: off` to `.compound-engineering/config.local.yaml` (or the committed `config.yaml`). The review skills read it before choosing a peer, keep every local reviewer, and report "disabled by checkout config" ([cross-model-review.md:41](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-code-review/references/cross-model-review.md#L41)). The file is not inherited by new worktrees; [#1803](https://github.com/EveryInc/compound-engineering-plugin/issues/1803) (open) asks for a user-level layer. This gate is skill instructions, so it holds only as far as the model follows them.
- **K-03, per machine:** start Grok with `CROSS_MODEL_PEERS=none` in its environment (for example `export CROSS_MODEL_PEERS=none` in your shell profile). The code-review, doc-review and pov workers refuse every provider the list does not name before any content leaves ([cross-model-adversarial-review.sh:452](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-code-review/scripts/cross-model-adversarial-review.sh#L452), [cross-model-doc-review.sh:499](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-doc-review/scripts/cross-model-doc-review.sh#L499), [cross-model-pov.sh:434](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-pov/scripts/cross-model-pov.sh#L434)). Run on the scripts at the pin (Assay table); that Grok passes the variable to its terminal commands is *inferred*, not observed in a session.
- **K-03, per request:** say "no external review" when you call `ce-code-review` or `ce-doc-review`; a live prohibition overrides the default ([ce-code-review/SKILL.md:31](https://github.com/EveryInc/compound-engineering-plugin/blob/1fd12d69812b9c48e0b054bb4a000de2cb37f744/skills/ce-code-review/SKILL.md#L31)).
