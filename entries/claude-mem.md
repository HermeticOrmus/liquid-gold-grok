# claude-mem

Persistent memory for coding agents: hooks record each session's prompts and tool calls into a local SQLite database through a background worker, an observer model compresses them into observations and summaries, and in Claude Code the next session starts with the relevant ones injected as context. An MCP server and a `mem-search` skill search the store on request.

## Who it is for

People who want an agent to remember decisions, fixes and project context across sessions without writing notes by hand, and who already use Claude Code (the default observer runs on it) or will configure another model provider for the observer.

## Install

Not in the marketplace yet. The upstream README documents Claude Code (`/plugin marketplace add thedotmack/claude-mem`) and Grok Bot (`npx claude-mem install --ide grok-bot`), not Grok Build. The line that installs this edition in Grok is below, for reference only.

```bash
grok plugin install "https://github.com/thedotmack/claude-mem.git@e290f3dd7097715c8c481a1e386fe03beb48ed81#plugin" --trust
```

Without `#plugin`, Grok installs a different edition from the repository root (K-07), and `grok plugin marketplace add thedotmack/claude-mem` cannot sync the repository (K-08).

## Why it is watch

In Grok, at the pin, claude-mem records nothing. Its runtime dependencies (`zod`, `shell-quote`, the tree-sitter grammars) are installed only by its `Setup` hook, which runs `bun install --production` in the plugin folder ([version-check.js:186](https://github.com/thedotmack/claude-mem/blob/e290f3dd7097715c8c481a1e386fe03beb48ed81/plugin/scripts/version-check.js#L186)). Grok's hook events have no `Setup`, and Grok skips event names it does not recognize ([10-hooks.md:162](https://github.com/xai-org/grok-build/blob/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8/crates/codegen/xai-grok-pager/docs/user-guide/10-hooks.md#L162)). We ran every hook in the installed plugin with the JSON shape Grok sends: each one printed `error: Cannot find module 'zod/v3'` and `claude-mem: hook command failed (exit 1)`, then exited 0, so Grok records success and nothing is stored (K-01). Running the install step by hand fixes that, and then capture works: the worker starts, and prompts and tool calls land in the database. Memory still does not come back. Past context is delivered as SessionStart `additionalContext`, which Grok ignores (K-02); the search server the README offers for recall on request ([README.md:261](https://github.com/thedotmack/claude-mem/blob/e290f3dd7097715c8c481a1e386fe03beb48ed81/README.md#L261)) does not start, because its launcher reads `CLAUDE_PLUGIN_ROOT` from an environment Grok sets only for hooks (K-03); Stop summaries are skipped because the adapter does not read Grok's `lastAssistantMessage` (K-04); and the default observer needs the Claude Code CLI and its login, so a Grok-only setup queues events that are never compressed (K-06). Four breaks are open, one of them held in an open pull request, so the entry waits. Most of the fixes are small, and one was proven at the pin: a single `env` line in `plugin/.mcp.json` makes the search server start under Grok with all 15 tools (K-03).

Telemetry is a separate fracture: the worker sends anonymous usage events to PostHog by default, with no prompt on a plugin install, while SECURITY.md says "Claude-mem does not collect telemetry" (K-05). `DO_NOT_TRACK=1` turns it off, and we checked that it does.

The vessel already carries one Grok seal: [#3295](https://github.com/thedotmack/claude-mem/pull/3295) renamed an MCP tool called `__IMPORTANT` that made Grok Build reject the whole server (K-11).

## What it can execute

- **Hooks** (every command first prepends `~/.nvm`, `~/.local/bin`, `/usr/local/bin` and `/opt/homebrew/bin` to `PATH`, and searches Claude Code's plugin cache when `CLAUDE_PLUGIN_ROOT` is unset). What each does in Grok, from the sandbox run below:
  - `Setup`: [version-check.js](https://github.com/thedotmack/claude-mem/blob/e290f3dd7097715c8c481a1e386fe03beb48ed81/plugin/scripts/version-check.js) runs `bun install --production` and a version check. Grok skips the event, so nothing installs the dependencies (K-01).
  - `SessionStart`: `worker-service.cjs start` starts the worker daemon. Works once the dependencies exist. Grok ignores the `async` and `shell` keys ([config.rs:101](https://github.com/xai-org/grok-build/blob/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8/crates/codegen/xai-grok-hooks/src/config.rs#L101)), so it runs in the foreground (1.9 s in the sandbox).
  - `SessionStart`: `hook claude-code context` prints past observations as `additionalContext`. Grok ignores SessionStart output (K-02).
  - `UserPromptSubmit`: `session-init` records the session and the prompt. Works. Its optional per-prompt recall (`CLAUDE_MEM_SEMANTIC_INJECT`, off by default) would be discarded (K-02).
  - `PreToolUse`, matcher `Read` (Grok maps it to `read_file`): `file-context` looks for `tool_input.file_path`; Grok's `read_file` sends `target_file`, so it returns nothing (K-04).
  - `PostToolUse`, matcher `*`: `observation` stores the tool name, input and result and queues them for the observer. Works, with Grok's own tool names (`run_terminal_command`, `todo_write`).
  - `Stop`: `summarize` ignores Grok's `lastAssistantMessage` and tries the transcript as Claude Code JSONL; no summary request reached the worker (K-04).
  - `SessionEnd`: `session-end` ran and exited 0.
- **Worker:** a Bun process serving the viewer and API on `127.0.0.1` port 37700 plus your user id modulo 100, writing `~/.claude-mem/` (SQLite database, Chroma store, logs, `settings.json`, `telemetry.json` with a random install id, database backups). Vector search starts `uvx chroma-mcp` (a pinned version) when `uv` is present. The observer runs the Claude Agent SDK through the `claude` CLI and reads Claude Code's OAuth token from the system credential store ([oauth-token.ts:24](https://github.com/thedotmack/claude-mem/blob/e290f3dd7097715c8c481a1e386fe03beb48ed81/src/shared/oauth-token.ts#L24)).
- **MCP servers:** `mcp-search`, stdio: a `node -e` launcher finds `scripts/mcp-server.cjs` and runs it (15 tools). It does not start in Grok as shipped (K-03).
- **Scripts the skills run when you invoke them:** `wowerpoint` installs `notebooklm-py` from PyPI without a version pin and uploads the document to Google NotebookLM; `cloud-sync` connects to `sync.cmem.ai`; `mode-creator` can configure a Telegram bot; `agent-cost-report` fetches OpenRouter's model price list; `version-bump` and `oh-my-issues` are maintainer workflows for a plugin repository and a GitHub backlog. Each skill states this in its own text.
- **Network:** PostHog (`us.i.posthog.com`), on by default (K-05); Anthropic's API through the observer by default; Gemini, OpenRouter or an OpenAI-compatible endpoint when configured; the cmem.ai gateway when CMEM Pro is configured; `sync.cmem.ai` only when a sync hub is set; the npm registry for the dependency install and PyPI for `chroma-mcp`.
- **Disclosed in its README:** partly. SECURITY.md lists the provider paths, the OAuth read, Chroma and the registries ([SECURITY.md:161](https://github.com/thedotmack/claude-mem/blob/e290f3dd7097715c8c481a1e386fe03beb48ed81/SECURITY.md#L161)), and the docs site has a telemetry page; the README never mentions telemetry, and SECURITY.md denies it (K-05).

## Workarounds
