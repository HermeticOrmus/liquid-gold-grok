# last30days

Researches any topic across Reddit, X, YouTube, TikTok, Hacker News, Polymarket, GitHub and the web for the last 30 days, scores what it finds by upvotes, likes and money at stake, and writes a cited brief. One skill drives a Python engine that the agent runs through its shell.

## Who it is for

People who want to know what the crowd is saying about a product, a person or a trend, with quotes and links they can check, and who are willing to give the engine optional keys (ScrapeCreators, an X bearer or xAI key) for the sources that need them.

## Install

Not in the marketplace yet. The upstream install line is below, for reference only.

```bash
grok plugin install mvanhorn/last30days-skill --trust
```

## Why it is watch

On Linux, answering no to browser cookies does not stop the engine from reading them. The skill's own setup asks before any cookie read and promises that "a skip or no answer is never consent" ([SKILL.md:542](https://github.com/mvanhorn/last30days-skill/blob/5103ba478b380552207a3754b74c7655d64208cd/skills/last30days/SKILL.md#L542)); its Security section says it "does not access browser cookies unless explicitly configured or consented" ([SKILL.md:2415](https://github.com/mvanhorn/last30days-skill/blob/5103ba478b380552207a3754b74c7655d64208cd/skills/last30days/SKILL.md#L2415)). But every research run loads its config in cookie-read mode ([last30days.py:2894](https://github.com/mvanhorn/last30days-skill/blob/5103ba478b380552207a3754b74c7655d64208cd/skills/last30days/scripts/last30days.py#L2894)), Linux always counts as an "extra host" ([env.py:913](https://github.com/mvanhorn/last30days-skill/blob/5103ba478b380552207a3754b74c7655d64208cd/skills/last30days/scripts/lib/env.py#L913)), and on extra hosts two lookups run before the `FROM_BROWSER` gate: the `agentcookie` sidecar when it is on `PATH`, and any Chrome listening for DevTools on `127.0.0.1:18800` or `9222` plus the display number, which the engine asks for `Network.getAllCookies` ([chrome_cdp.py:285](https://github.com/mvanhorn/last30days-skill/blob/5103ba478b380552207a3754b74c7655d64208cd/skills/last30days/scripts/lib/chrome_cdp.py#L285)). A "no" in setup writes only `SETUP_COMPLETE=true` ([last30days.py:3336](https://github.com/mvanhorn/last30days-skill/blob/5103ba478b380552207a3754b74c7655d64208cd/skills/last30days/scripts/last30days.py#L3336)) and prints "Future runs will auto-detect your browsers." ([setup_wizard.py:850](https://github.com/mvanhorn/last30days-skill/blob/5103ba478b380552207a3754b74c7655d64208cd/skills/last30days/scripts/lib/setup_wizard.py#L850)). We ran exactly that at the pin: after `FROM_BROWSER=off ... setup`, the next research config load took a fake x.com cookie pair from a local stand-in for Chrome and selected the cookie scraper with source `chrome cdp` (K-01). CONFIGURATION.md describes these Linux lookups, but the same file says a "no" "skips all cookie reads", so nothing tells a user who declined. Two lines in the engine's `.env` close it, and we proved them at the pin; the entry still waits, as axiorank did, because a consent promise has to hold for the person who answers the plugin's question, not only for the one who read this card.

The rest of the vessel is strong. Grok loads one skill and nothing else: no hooks, no MCP servers. The skill's Security section lists its endpoints, keys and writes one by one, and two seals at the pin matter to Grok users: [#1005](https://github.com/mvanhorn/last30days-skill/pull/1005) made the Grok CLI an opt-in X backend, so a Grok Build login is never used for X searches on its own, and [#1142](https://github.com/mvanhorn/last30days-skill/pull/1142) removed the SessionStart hook that read the engine's credential file in every session.

## What it can execute

- **Hooks:** none at the pin (`grok inspect`: `hooks: []`).
- **Scripts:** the skill tells the agent to run `scripts/last30days.py` (research, `setup`, `doctor`, `library`, `queue`) with a Python 3.12 it finds or, when `uv` is present, downloads (`uv python install 3.12`, announced). `setup` runs `brew install yt-dlp` when Homebrew is present and `npx -y @mvanhorn/printing-press-library@0.1.16 install <digg|arxiv|techmeme> --cli-only` (the installer is pinned; the CLIs it fetches were not assessed). The vendored `bird-search` client (MIT) runs under Node for X. With `LAST30DAYS_X_BACKEND=grok` pinned, the engine runs `grok` as a child process with its own throwaway `HOME`.
- **MCP servers:** none. The repo's `mcp/` folder holds a separate Go server that the plugin does not register.
- **Network:** queries go to the sources the README names: Reddit (public pages, plus the `arctic-shift.photon-reddit.com` archive), Hacker News (`hn.algolia.com`), Polymarket (`gamma-api.polymarket.com`), YouTube through `yt-dlp`, GitHub through `gh`, and, with keys, ScrapeCreators, the X API, xAI, Xquik, Perplexity, Brave, Exa, Serper, Parallel and OpenRouter. With no host search signal the keyless web floor queries DuckDuckGo, then Startpage (K-02). A configured reasoning key also receives the topic and snippets for reranking (K-05). The ScrapeCreators GitHub signup runs its device flow through `api.scrapecreators.com` ([setup_wizard.py:917](https://github.com/mvanhorn/last30days-skill/blob/5103ba478b380552207a3754b74c7655d64208cd/skills/last30days/scripts/lib/setup_wizard.py#L917)). Publishing to `ht-ml.app` and Slack or webhook delivery from the watchlist run only when asked.
- **Credentials and local reads:** X cookies from a browser (behind consent on a MacBook; see K-01 for Linux), Truth Social cookies only when `FROM_BROWSER` names a browser, keys from `~/.config/last30days/.env`, the macOS Keychain or `pass`, and the Grok CLI's stored login when that backend is pinned.
- **Writes:** `~/.config/last30days/.env` (mode 0600), briefs and a SQLite store under `~/Documents/Last30Days` unless `LAST30DAYS_MEMORY_DIR` is set.
- **Disclosed in its README:** partly. The README and the skill's Security section name the sources, the keys and the cookie reads ([SKILL.md:2394](https://github.com/mvanhorn/last30days-skill/blob/5103ba478b380552207a3754b74c7655d64208cd/skills/last30days/SKILL.md#L2394)); the Linux cookie lookups after a "no" (K-01) are not, and Startpage appears only in the CHANGELOG (K-02).

## Workarounds

- **K-01:** add two lines to `~/.config/last30days/.env`: `FROM_BROWSER=off` and `AGENTCOOKIE=off`. Run at the pin: with both lines, the stand-in DevTools endpoint received no request, the stub `agentcookie` was not called, and X stayed unconfigured. `FROM_BROWSER=off` alone still let the sidecar run. Passing `--no-browser-cookies` on each run also turns every cookie read off. If you want X without cookies, use `X_BEARER_TOKEN` or `XAI_API_KEY` as the skill offers.
- **K-02:** let the engine know the host searches the web: the skill tells the agent to `export LAST30DAYS_NATIVE_SEARCH=1` when it has a web search tool, and Grok has `web_search`. Run at the pin with HTTP stubbed: with the flag, the keyless floor contacted no host.
- **K-03:** when a setup command fails with `can't open file .../skills/last30days/scripts/last30days.py`, ask the agent to run it from the folder that holds the loaded `SKILL.md` (`"${SKILL_DIR}/scripts/last30days.py"`). Not run in a Grok session.
