**Title:** Pass CLAUDE_PLUGIN_ROOT and CLAUDE_PLUGIN_DATA to the MCP server explicitly

**Body:**

With grok 1.0.44, `grok mcp doctor hindsight` in a clean Grok home reports `server started`, then `handshake failed (connection closed: initialize response)`. The server log contains:

```
mkdir: cannot create directory '': No such file or directory
```

`scripts/run_mcp.sh` builds its paths from `${CLAUDE_PLUGIN_DATA}` and `${CLAUDE_PLUGIN_ROOT}` in its environment (lines 6 to 8). Grok replaces those tokens inside `.mcp.json` strings (`plugin_substitute` in `xai-grok-config/src/mcp_servers.rs`, line 157) but does not set them as environment variables for MCP processes; it sets them for hooks. `.mcp.json` passes only the script path as an argument, so the script sees both variables empty. Exporting `CLAUDE_PLUGIN_DATA` by hand gets past `mkdir`, then pip fails on `/requirements.txt` for the same reason.

Suggested change to `.mcp.json`:

```json
{
  "mcpServers": {
    "hindsight": {
      "command": "bash",
      "args": ["${CLAUDE_PLUGIN_ROOT}/scripts/run_mcp.sh"],
      "env": {
        "CLAUDE_PLUGIN_ROOT": "${CLAUDE_PLUGIN_ROOT}",
        "CLAUDE_PLUGIN_DATA": "${CLAUDE_PLUGIN_DATA}"
      }
    }
  }
}
```

I have not confirmed that Grok substitutes tokens inside `env` values; if it does not, passing the two paths as extra arguments to `run_mcp.sh` works the same way, since `args` substitution is confirmed.
