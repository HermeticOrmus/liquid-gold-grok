**Title:** LLM API key is passed on the hindsight-embed command line; README wording on outbound calls

**Body:**

Two related points about keys and outbound calls.

1. When the plugin starts the local daemon, `scripts/lib/daemon.py` adds `--env HINDSIGHT_API_LLM_API_KEY=<key>` to the `hindsight-embed profile create` arguments (line 195, and line 297 for the background pre-start). Command-line arguments are visible to other local users in the process list while the command runs. Passing the key only through the child process environment (which `_run_embed` already sets) would avoid that. Where `hindsight-embed` stores the profile afterwards is outside this plugin and I did not check it.

2. The README's Network & credentials section (line 99) says outbound calls happen only when you configure them. `scripts/lib/llm.py` (line 91) picks up an existing `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` or `GROQ_API_KEY` automatically, so anyone who already has one of those exported will have transcripts sent to that provider with no plugin-specific step. Install step 2 does say "auto-detected"; a sentence in line 99 saying that an existing key counts as configuring it would make the two sections agree.
