**Title:** README: Grok Build can install the plugin as it is

**Body:**

With grok 1.0.44 in a clean Grok home, the plugin installs from the repository and loads all 27 skills the manifest declares:

```text
$ grok plugin install https://github.com/mattpocock/skills.git@d81f3a183412e71a5b1e84ca21bc1a35eea03a60 --trust
Installed 1 plugin(s) from ...: mattpocock-skills
$ grok plugin details mattpocock-skills
    mattpocock-skills v1.2.3
  components: 27 skill dir(s), 0 command dir(s), 0 agent dir(s)
```

Grok reads `.claude-plugin/plugin.json` directly, so no second manifest is needed. The Installation section (README.md line 25) covers the Claude Code plugin and `npx skills`. A one-line Grok entry would save Grok users from picking the copy install and getting every skill twice later:

```bash
grok plugin install mattpocock/skills --trust
```

(Checked in a clean Grok home: `Installed 1 plugin(s) from mattpocock/skills: mattpocock-skills`.)

The harness-neutral subagent wording from #781 is what makes this work well outside Claude Code.
