**Title:** State the license in the repository, and add Grok Build to the install guide

**Body:**

The plugin installs cleanly in Grok Build (grok 1.0.44, clean Grok home, commit `2c8af03`), and Grok registers the MCP server: `grok plugin details figma` reports `figma v2.2.124` and `components: 1 skill dir(s), 0 command dir(s), 0 agent dir(s), MCP servers`. xAI's official Grok marketplace lists it.

Two gaps:

1. **License.** There is no LICENSE file in the tree, `.claude-plugin/plugin.json` has no `license` field, and the GitHub API reports no license for the repository. The README (line 12) says that using the server and the related resources, including these skills, means agreeing to the Figma Developer Terms, which live at a URL that can change. Catalogs that record the license of a pinned commit have nothing to point at. A `LICENSE` or `TERMS.md` file in the repository (even one that states the Figma Developer Terms apply and links them), plus a `license` field in the manifest, would fix that.
2. **Grok Build install.** The install guide (README.md line 38) covers VS Code, Cursor, Claude Code, Gemini CLI and other editors. A Grok Build section could read:

   ```bash
   grok plugin install figma@xai-official --trust
   ```

   or, without xAI's marketplace registered, `grok plugin install figma/mcp-server-guide --trust`.

This description proposes the changes; it does not choose license terms for Figma.
