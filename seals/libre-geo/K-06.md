**Title:** fix(geo-schema): stop pointing the agent at ~/.claude/skills

**Body:**

v1.0.0 moved the PDF report script off `~/.claude/skills/geo/scripts/`, a path that exists only after the pre-1.0 copy install (CHANGELOG line 22). The `geo-schema` agent still uses that path. `agents/geo-schema.md` line 19:

```bash
python3 ~/.claude/skills/geo/scripts/fetch_page.py <url> page
```

With the plugin installed through a marketplace, in Claude Code or in Grok Build, the file is not there, and line 17 of the same agent explains why the fallback hurts: WebFetch strips `<head>`, which removes the JSON-LD blocks a schema audit needs. The agent came unchanged from geo-seo-claude (NOTICE.md), where the copy install made the path valid. CONTRIBUTING.md line 31 already states the rule: reference shipped files by `${CLAUDE_SKILL_DIR}`, never by a path under `~/.claude`.

Change:

1. In `skills/geo-audit/SKILL.md` and `skills/geo/SKILL.md`, where they delegate to `geo-schema`, pass the script's absolute path in the subagent task: `"${CLAUDE_SKILL_DIR}/scripts/fetch_page.py"` from the `geo` skill, or `"${CLAUDE_SKILL_DIR}/../geo/scripts/fetch_page.py"` from a sibling skill, the same form `geo-report-pdf` uses.
2. In `agents/geo-schema.md`, run the path given in the task; when none was given, fetch the raw HTML with `curl -sL <url>`, which keeps `<head>`, and read the `application/ld+json` blocks from it.
3. Note the change in NOTICE.md, since the agent is no longer unchanged from upstream.
