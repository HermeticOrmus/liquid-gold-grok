Evidence for #446 from an install of pstack 0.15.5 in Grok Build (grok 1.0.44, clean Grok home, commit `2eb7ed4`):

- `grok plugin install https://github.com/cursor/plugins.git@2eb7ed4613cfc8f098dfe464a23680ea44d84c5e#pstack --trust` installs it. Grok finds no manifest it reads (only `.cursor-plugin/plugin.json` exists), so it discovers the 47 skills and 2 agents by folder, names the plugin `pstack` after the folder, and shows no version in `grok plugin details`.
- The principle skills and the playbook text are plain Markdown and read fine.
- The orchestration layer assumes Cursor: `/setup-pstack` writes `~/.cursor/rules/pstack-models.mdc` (setup-pstack/SKILL.md line 8) and asks through `AskQuestion` (line 22); `poteto-mode` spawns `Task` subagents with Cursor model slugs (poteto-mode/SKILL.md line 93); babysit runs its watcher under `/loop` (playbooks/babysit.md line 12). The README documents only `/add-plugin pstack` (README.md line 15).

Two small changes would make the marketplace listing honest for Grok users without a separate port:

1. A README note under install: which skills work as they are in Grok Build (the principles and the single-agent playbooks), and that model routing through `/setup-pstack` is Cursor-only.
2. A `.claude-plugin/plugin.json` (Grok reads it) with the name, version, description, author and license from `.cursor-plugin/plugin.json`, so `grok plugin details pstack` shows the version.
