**Title:** security-guidance: pattern warnings depend on the exact tool names Edit, Write, MultiEdit, NotebookEdit

**Body:**

The plugin installs and validates in Grok Build (grok 1.0.44), which reads `.claude-plugin/plugin.json` and `hooks/hooks.json` as they are. The pattern layer is the part that needs no API key, so it is the part most likely to help there.

`hooks/security_reminder_hook.py` line 2346 only checks content when `tool_name` is one of `Edit`, `Write`, `MultiEdit` or `NotebookEdit`, and `hooks.json` matches the same four names. Piping the same `PostToolUse` payload into the hook twice, once with `tool_name: "Write"` and once with another edit tool name (`StrReplace`), gives the `yaml.load()` warning for the first and no output for the second. An agent whose edit tools carry other names gets no pattern warnings and no signal that the layer is idle.

Suggested fix: when `tool_input` carries a `file_path` plus new content (`content`, `new_string`, or `edits`), run the pattern check whatever the tool is called, or read a small alias list from an environment variable, and add the host's edit tool names to the `PostToolUse` matcher.

I have not confirmed which tool names a Grok Build session reports to hooks, so this is filed as a compatibility question with a reproduction, not as a confirmed Grok failure.
