**Title:** Add a LICENSE file

**Body:**

Six of the eight vendor manifests in this repository declare `"license": "MIT"` (`.claude-plugin`, `.codex-plugin`, `.github/plugin`, `.grok-plugin`, `.kimi-plugin` and `.plugin`), and so does `skills/supabase-postgres-best-practices/SKILL.md`. The repository itself has no license file at `2c6d02d`, and the GitHub API reports none:

```
$ gh api repos/supabase-community/supabase-plugin/license
{"message":"Not Found", ... "status":"404"}
```

Plugin catalogs and anyone redistributing the plugin look for the license text in the repository, next to the code. The skills are synced from `supabase/agent-skills`, which GitHub reports as MIT, so an MIT `LICENSE` at the root (with the same copyright line as that repository) would match what the manifests already say. The Cursor manifest and `gemini-extension.json` could gain the same `license` field.
