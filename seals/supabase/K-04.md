**Title:** supabase skill: show the feedback issue before posting it, and skip the `.mcp.json` step when a plugin provides the server

**Body:**

Two small changes, both seen in the copy the plugin ships (`skills/supabase/` at supabase-community/supabase-plugin `2c6d02d`).

**1. Feedback issues are posted without the user seeing them.** `references/skill-feedback.md` asks permission to send feedback (step 1), drafts the issue from the conversation (step 2), then creates it on the public `supabase/agent-skills` repository (step 3). The user agrees to send feedback before the draft exists and never sees what is posted, though the body is built from their task. Suggested step 3:

```markdown
3. **Show, then submit:** show the user the exact title and body. Remove anything
   from their project the maintainers do not need (names, data, keys, URLs). Create
   the issue only after the user says yes to this text.
```

**2. The troubleshooting step writes a project `.mcp.json` that a plugin install does not use.** `SKILL.md` lines 107 and 108 tell the agent to create a project `.mcp.json` pointing at `https://mcp.supabase.com/mcp` when none exists. When the skill arrives through the plugin, the plugin already defines a server named `supabase`. In Grok Build (grok 1.0.44, clean home, plugin installed), a project `.mcp.json` with that server makes `grok mcp doctor` report `.mcp.json 0 servers` and keep `plugin: supabase`, so the file only adds clutter to the user's repository. Suggested wording:

```markdown
2. **Check the MCP configuration:**
   If the Supabase plugin is installed, it already provides the `supabase` server; go to
   step 3. Otherwise, verify the project root has a valid `.mcp.json` with the correct
   server URL, and create one pointing to `https://mcp.supabase.com/mcp` if it is missing.
```
