**Title:** SKILL.md: pin the `npx` version to the release instead of `@latest`

**Body:**

Plugin installs are pinned to a commit: Grok Build and Claude Code marketplaces both record a commit SHA, and v0.0.191 installs cleanly in Grok Build 1.0.44. But `skills/modern-web-guidance/SKILL.md` tells the agent to run `npx -y modern-web-guidance@latest` (lines 38, 65 and 75, and the allowlist advice on line 94). So the code that runs is whatever npm serves when the agent calls it, not the version the user installed, and `-y` installs it without a prompt. On the date of this report `latest` is 0.0.191, the same as the plugin, so the two agree; they part at the first release after it.

The skill already carries a `--skill-version` stamp that the CLI checks, so the release process knows which version it is building.

Suggested fix: have the release step write the exact version into SKILL.md (`npx -y modern-web-guidance@0.0.191 search ...`, and the matching allowlist line). The "content does not go stale" goal still holds, because updating the plugin moves both the guides and the CLI version together.
