**Title:** Say that sprites are billed, and ask before creating one the user did not ask for

**Body:**

The plugin is careful about every step that loses data or widens access: `references/safety.md` (line 3) asks for confirmation before destroy, restore, network policy changes and public exposure, and the README explains the full-access trade-off on the consent screen clearly.

Creating a sprite is the one step with a cost that has no such line. The main skill tells the agent to prefer Sprites over the local shell when "builds, tests, or dependency installs would pollute or overload the local machine" (`skills/sprites/SKILL.md`, lines 25 and 29), `references/compute.md` routes heavy installs, compiles and integration tests to a sprite (line 13) and starts with "Select or create" (line 20), with no step that asks first. Sprites bill CPU, RAM and hot storage per hour of active use (sprites.dev pricing FAQ), and the only mention of cost in the plugin is "Sprites can idle cheaply" (`compute.md`, line 58). A Grok user who asked for a test run can find it ran on a billed sprite, with their code copied there.

Proposed change:

1. One line in the README, near "What you can do": sprite usage is billed to the Fly.io organization you sign in with, with a link to pricing.
2. In `safety.md`, add to "Confirm before these actions": creating a sprite, or moving local code to one, when the user did not ask for a sprite or a sandbox. The existing routing table can stay; it then decides what to suggest instead of what to do.
