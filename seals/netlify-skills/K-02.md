**Title:** Grok Build: the plugin installs as `netlify-skills`, not `netlify`; add the license to the manifests

**Body:**

Thanks for the Grok Build support. The plugin installs and loads cleanly: with grok 1.0.44 in a clean Grok home, `grok plugin install https://github.com/netlify/context-and-tools.git@47d1f147cc134043593574b69e6483e1f6ae16ad --trust` installs `netlify-skills v1.6.0`, and `grok inspect --json` lists all 15 skills and the hosted `netlify` MCP server.

Two small things a Grok user runs into:

1. **Name.** The Grok Build section (README.md line 156) says to find and install **netlify** in the xAI marketplace, and xAI's catalog lists the entry as `netlify`. The plugin's own manifest (`.grok-plugin/plugin.json` line 2) names it `netlify-skills`, and that is the name Grok uses after the install. In a clean home with the xAI marketplace added, `grok plugin install netlify@xai-official --trust` prints `Installed 1 plugin(s) from xAI Official: netlify-skills`, and then `grok plugin details netlify` exits 1 with `Plugin "netlify" not found`. Suggested fix: one sentence in the Grok section, for example "It installs as `netlify-skills`; use that name with `grok plugin details` and `grok plugin uninstall`." Renaming the Grok manifest to `netlify` would also line the two up, but it changes the name for anyone already installed, so the README line is the smaller change.

2. **License.** `LICENSE` (MIT) and `package.json` state the license, but neither `.grok-plugin/plugin.json` nor `.claude-plugin/plugin.json` has a `license` field, and the README has no license section. Suggested fix: add `"license": "MIT"` to both manifests (the generated `agent-plugin/plugin.json` already carries it).
