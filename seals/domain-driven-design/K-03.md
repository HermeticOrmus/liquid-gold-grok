**Title:** fix(domain-driven-design): keep money exact in the Money value object

**Body:**

The skill's TypeScript `Money` value object (`plugins/domain-driven-design/skills/domain-driven-design/SKILL.md` lines 203 to 250) stores amounts as a JavaScript `number` and rounds with `Math.round(amount * 100) / 100` (line 217). Binary floating point makes that rounding wrong for some inputs, and the fixed two decimals are wrong for currencies with zero or three minor digits. Run with Node v26.8.1:

```text
Math.round(1.005 * 100) / 100   ->  1      (expected 1.01)
Math.round(100.5 * 100) / 100   ->  100.5  (JPY has no minor unit)
```

This is the pattern the skill offers as the model for a value object, so it is the one people copy. The sibling `ledger-design` plugin in LibreFinTech already says "integer minor units always".

Changes:

1. Store `minor: bigint` plus the currency's exponent (ISO 4217: USD 2, JPY 0, BHD 3). `of(amount: string, currency)` parses a decimal string into minor units with no float step; `add` and `multiply` work on `bigint`; `toString` formats with the exponent.
2. Keep equality by value (`minor` and `currency`), and keep the non-negative check as a documented choice, with a note that refunds and credits need either a signed amount or a separate direction.
3. K-04: in the `/ddd model` worked example (`commands/ddd.md` line 134), move "Total must be >= $10.00" from item add to confirmation. As written, an order can never start with an item under $10.
