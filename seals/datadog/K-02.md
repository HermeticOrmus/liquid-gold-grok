**Title:** README: who asks for the site, and the two skills

**Body:**

Two small README changes.

**1. The site form is Grok's.** Getting started, step 2 (line 18), says "The agent will guide you through selecting the correct Datadog MCP domain." In Grok it is the `/mcps` form, built from the `setup` block in `.dd_grok_mcp.json`, that asks for the site when the user presses `i`. Until a site is saved, Grok does not list the server at all: with grok 1.0.44 in a clean Grok home and the plugin installed at `083b478`, `grok inspect --json` shows the two skills and no MCP server, and `grok mcp list` says `No MCP servers configured`. A user who checks there after installing may think the server is missing. Suggested step 2:

```markdown
2. Type `/mcps` on the Grok Build command line, select the **datadog-grok** MCP server
   and press `i`. Grok asks for your Datadog site, then opens the sign-in in your browser.
   The server shows up in `grok mcp list` once a site is chosen.
```

**2. The skills are not listed.** The README and the manifest describe the MCP server only. The plugin also ships `ddconfig` and `datadog-app`, and `datadog-app` runs `npm create @datadog/apps@latest` when the user asks for a new Datadog App. Suggested section:

```markdown
## What's included

- The Datadog MCP server for your site.
- `ddconfig`: checks the connection and helps with sign-in, site and organization.
- `datadog-app`: scaffolds a new Datadog App with `npm create @datadog/apps@latest`,
  only when you ask for one.
```
