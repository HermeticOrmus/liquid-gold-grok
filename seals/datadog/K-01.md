**Title:** ddconfig: give the Domain Flow a path that works with Grok's site preference

**Body:**

Since v0.7.19 (c890dfc) the Datadog domain lives in Grok's setup preference instead of the MCP JSON file, which is a good fit for Grok: the `setup` block in `.dd_grok_mcp.json` makes Grok ask for the site the first time the user presses `i` on `datadog-grok` in `/mcps`. Two steps of the `ddconfig` Domain Flow were not updated with it:

- Step 1 (`skills/ddconfig/SKILL.md` line 42) reads the current domain "from the current domain in the registration file" and points to `mcp-settings.md` "for the file format".
- Step 3 (line 48) says "Edit the domain in the registration file following the editing rule in `mcp-settings.md`".

c890dfc removed the registration-file section and the editing rule from `references/mcp-settings.md`, whose line 34 says "ask Grok to update the preference setting then instruct the user to reauthorize". In grok 1.0.44 the agent has no tool for that. Grok writes the site only from its `/mcps` form, through the `x.ai/mcp/setup` request the UI sends (`xai-grok-shell/src/extensions/mcp.rs`, line 34), and the form opens only for a server whose setup is required, with no site saved (`xai-grok-pager/src/app/agent_view/modals.rs`, line 1755). Once a site is saved, `i` goes straight to sign-in. So the README's "just tell the agent you want to change the Datadog domain (or run `/ddconfig`)" (README line 18) has no path in Grok.

The README's `DD_MCP_DOMAIN` override does work. With grok 1.0.44 in a clean Grok home, the plugin installed at `083b478` and US1 saved, `DD_MCP_DOMAIN=mcp.datadoghq.eu grok inspect --json` lists `datadog-grok` at `https://mcp.datadoghq.eu/v1/mcp`.

Suggested Domain Flow for Grok:

```markdown
## Domain Flow

1. Show the current site from `whoami` (`dd_site`). If `whoami` is not available, say the
   current site could not be read.
2. Ask for the new site and resolve it to an MCP domain with the table in `mcp-settings.md`.
3. Tell the user to quit Grok and start it again with that domain, for example
   `DD_MCP_DOMAIN=mcp.datadoghq.eu grok`, then run `/mcps`, select the Datadog MCP
   server, and press `i` to sign in to the new site.
```

Step 3 names an environment variable, which the "Stay on script" rule in `mcp-settings.md` (line 13) forbids, so that rule needs an exception for this step. The other way is to ask the user to clear the saved site (Grok keeps it under `datadog-grok` in `mcp_preferences.json` in the Grok home) so that `/mcps` asks again; I have not driven that path in the UI.
