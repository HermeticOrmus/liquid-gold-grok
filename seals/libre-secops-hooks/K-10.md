**Title:** docs(hooks): say what the hooks do under Grok Build

**Body:**

The plugin README describes the hooks for Claude Code only. Two lines would tell a Grok Build user the truth.

1. **The session profile (K-10).** `session-start.sh` prints one plain line, which Claude Code adds to the session context. The hooks guide that grok 1.0.44 writes to `$GROK_HOME/docs/user-guide/10-hooks.md` says "For events like `SessionStart` or `Notification`, stdout is ignored" (line 505), so under Grok the line goes nowhere. Add under "What each hook does":

   > Under Grok Build the session-start line is not added to the session (Grok ignores SessionStart output). Run `bash hooks/session-start.sh </dev/null` in your project's root to read it.

   That command was run at `a874d37` in a sample project: exit 0 and the expected one-line profile.

2. **Install (K-12).** After the Claude Code install block, add:

   ```
   grok plugin marketplace add HermeticOrmus/LibreSecOps-Claude-Code
   grok plugin install libre-secops-hooks@libre-secops --trust
   ```

   and change "Restart Claude Code after installing" to "Start a new session after installing". Check the marketplace name against `.grok-plugin/marketplace.json` from PR #8 before merging.
