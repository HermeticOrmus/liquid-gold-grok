**Title:** fix(hooks): read the Grok hook envelope as well as Claude Code's

**Body:**

`pre-tool-use.sh` and `post-tool-use.sh` read `.tool_name` and `.tool_input.file_path`, and exit unless the tool is `Edit`, `Write` or `MultiEdit`. Grok's hook input is camelCase (`toolName`, `toolInput`; hooks guide `docs/user-guide/10-hooks.md` lines 267 to 278 and 473). It also adds snake_case aliases, so `.tool_name` and `.tool_input` are present (xai-org/grok-build `crates/codegen/xai-grok-hooks/src/event.rs` line 377, and the alias table is in the grok 1.0.44 binary). But the value is Grok's own tool name: an edit arrives as `search_replace`, `write` or `hashline_edit` (`crates/codegen/xai-grok-tools/src/types/claude_alias.rs` lines 47 to 52). The matcher still fires, because Grok maps `Edit|Write|MultiEdit` to those names for matchers only, and the scripts then see a tool name they do not accept and exit 0 with no output.

Reproduced outside a session: the `.env` edit that gets `permissionDecision: "ask"` with Claude Code's input, and the private-key file that gets a CRITICAL finding, both produce nothing when sent as `{"toolName":"search_replace","toolInput":{"file_path":"..."}}`.

Change, in both scripts:

```bash
TOOL_NAME="$(jq -r '.tool_name // .toolName // empty' <<<"$INPUT" 2>/dev/null || true)"
FILE_PATH="$(jq -r '.tool_input.file_path // .toolInput.file_path // .toolInput.path // empty' <<<"$INPUT" 2>/dev/null || true)"

case "$TOOL_NAME" in
  Edit|Write|MultiEdit|search_replace|write|hashline_edit) ;;
  *) exit 0 ;;
esac
```

One thing is not known from the guide or the source and must come from one real Grok session before this merges: the key Grok's `search_replace`, `write` and `hashline_edit` inputs use for the file path (`file_path`, `path`, or another; marked `?` here). Capture one payload with a throwaway hook (`cat > "$(mktemp)"` as a PostToolUse command), set the keys from what it shows, and add both envelopes to a test that feeds each script a fixture.

The output side needs no change: the guide documents `hookSpecificOutput.permissionDecision` (line 296) and PostToolUse `additionalContext`.
