**Title:** Grok Build: session context and skill telemetry hooks have no effect; say so in the README

**Body:**

Two of the plugin's hooks run in Grok Build but cannot do their job there. Neither hurts the user; both make the README's description of Grok support inaccurate.

1. **Session context.** `inject-claude-md.mjs` delivers the thin session context, the `knowledge-update` guidance and, in an empty folder, the greenfield guidance by printing them to stdout (line 84). Grok's hooks guide says `SessionStart` stdout is ignored (xai-org/grok-build, docs/user-guide/10-hooks.md line 505). Outside a session, with a Grok-shaped `SessionStart` payload in a Next.js folder, the script printed 9,943 bytes; in Grok none of it reaches the model, so the knowledge corrections the README promises at session start (line 111) do not arrive.

2. **Skill telemetry.** The `PostToolUse` hook is matched on `Skill` (hooks/hooks.json line 24) and the script accepts only the tool name `Skill` (posttooluse-skill-telemetry.mjs line 21). Grok maps the `Skill` matcher to a `skill` tool that exists only in its opencode tool set; its default agent loads a skill by reading `SKILL.md` with `read_file`. Run with Grok-shaped input (`tool_name` `read_file` on a plugin `SKILL.md`, or `skill`), the script sends nothing. That is the same outcome the README already describes for Cursor (line 163).

Suggested fix, README only:

- In the Hooks section, a line for Grok Build: session context is not injected there; run `/knowledge-update` at session start, or add a line to the project's `AGENTS.md` that loads it.
- In "Coverage by harness", name Grok next to Cursor as a harness whose skill loads are not counted.
