**Title:** session-start-profiler: the Vercel CLI version check queries npm without notice or an off switch

**Body:**

The Telemetry section of the README is precise about what leaves the machine and how to stop it. One call is not covered there or anywhere else in the README: the CLI version check in `session-start-profiler`.

When the session's folder is a Vercel, Next.js or eve project, or empty, and `vercel` is on `PATH`, `checkVercelCli()` (hooks/session-start-profiler.mjs line 626, called at line 851) runs `vercel --version` and then `npm view vercel version` (line 653), which asks the npm registry in the user's npm config for the latest `vercel` version. The README's Hooks section describes the profiler as "Scans config files and dependencies to set likely-skill hints" (README.md line 112). `VERCEL_PLUGIN_TELEMETRY=off` does not stop the check.

Reproduced outside a session at this commit, with a scratch `HOME`, stand-in `vercel` and `npm` binaries that log their arguments, and `fetch` stubbed: with a `SessionStart` payload in a folder whose `package.json` depends on `next`, the hook ran `vercel --version` and `npm view vercel version` and printed the "Vercel CLI is outdated" advice; with `VERCEL_PLUGIN_TELEMETRY=off` set, the telemetry POST disappeared and both commands still ran.

In Grok Build the call has no use at all: Grok ignores `SessionStart` stdout (xai-org/grok-build, docs/user-guide/10-hooks.md line 505), so the upgrade advice never reaches the model. The plugin's own `detect-agent` bundle already reports `grok` when `GROK_PLUGIN_ROOT` is set.

Proposed change, any one of which closes it:

1. List the check in the README's Hooks section: it runs `vercel --version` and `npm view vercel version` at session start in activated projects.
2. Give it an off switch: honor `VERCEL_PLUGIN_TELEMETRY=off`, or a dedicated variable such as `VERCEL_PLUGIN_CLI_CHECK=off`.
3. Skip it when the detected harness ignores `SessionStart` output (Grok), since nothing can read the result.

Doing 1 and 2 together keeps the advice for Claude Code users and tells everyone what runs. A short `timeout` on the `SessionStart` entries (as #129 asks) would also bound the two 3-second `execFileSync` calls and the 3-second telemetry `fetch`, which together can pass Grok's 5-second default for observe hooks.
