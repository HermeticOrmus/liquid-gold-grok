**Title:** Grok Build: document the install, and say that hooks need the epic binary

**Body:**

The repository ships a Grok manifest (`.grok-plugin/plugin.json`) and Grok hooks (`.grok-plugin/hooks.json`), and `grok plugin install https://github.com/epicsagas/epic-harness.git@7abf3f1 --trust` installs cleanly with grok 1.0.44: all 27 skills load.

The hooks and the `harness-mem` MCP server run the `epic` binary, which the plugin folder does not contain. In a clean Grok home:

- each hook prints `[harness] epic not found, skipping ...` or nothing, and exits 0;
- `grok mcp doctor` reports `harness-mem` failing its handshake, with `sh: line 1: exec: epic: not found` in the server log.

The README's install section covers Claude Code (which "auto-installs the binary"), Codex, agy and a binary-only path, and does not mention Grok Build anywhere. The root `plugin.json`, which Grok reads before `.grok-plugin/plugin.json`, describes the plugin as loaded by agy, Claude Code and codex.

Suggested fix: a "Grok Build" install section that installs a pinned binary version first (for example `cargo binstall epic-harness@0.8.8`), then the plugin, and mentions the telemetry default; and Grok in the root `plugin.json` description.

A related detail: in `.mcp.json`, Grok substitutes the plain `${GROK_PLUGIN_ROOT}` token but not `${GROK_PLUGIN_ROOT:-}`, so `grok mcp doctor` shows the launcher as `for d in "" "" .` and the `target/release/epic` candidate is never tried.
