**Title:** Grok Build ignores SessionStart output, so the using-superpowers bootstrap does not load there

**Body:**

The README's Grok Build section (line 187 at `8ca22db`) installs Superpowers from xAI's marketplace, and with grok 1.0.44 the plugin installs cleanly and `grok inspect` lists all 15 skills and the hook file.

The bootstrap depends on the SessionStart hook: `hooks/session-start` prints `skills/using-superpowers/SKILL.md` as `hookSpecificOutput.additionalContext`. Grok's own hooks guide (line 505 of `docs/user-guide/10-hooks.md` in xai-org/grok-build, also bundled with grok 1.0.44) says: "For events like `SessionStart` or `Notification`, stdout is ignored." So in a Grok session the skills load and can trigger on their descriptions, but the "check for a skill before every task" instruction never reaches the model.

I have not run a Grok session to watch this; the evidence is Grok's documentation and the hook script's output format. Running the script outside a session with `CLAUDE_PLUGIN_ROOT` set gives valid JSON, so the script is fine; the harness does not read it.

Suggested fix: in the Grok Build install section, tell users to start a session with `/using-superpowers`, or to add one line to their project `AGENTS.md` (Grok reads it every session), for example "Before any task, load the superpowers using-superpowers skill and follow it." A Grok row in the Platform Adaptation list (see the related draft for `references/grok-tools.md`) could say the same.
