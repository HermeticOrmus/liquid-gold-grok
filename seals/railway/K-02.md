**Title:** Grok Build: the auto-approve hook has no effect; document it, and the telemetry tags

**Body:**

The plugin installs cleanly in Grok Build (grok 1.0.44, clean Grok home: `grok plugin install railway@xai-official --trust` installs `railway v1.6.1` from `plugins/railway`, and `grok inspect` loads `use-railway`, the hook file and the hosted MCP server). The `PreToolUse` hook, though, never approves anything in Grok, for two independent reasons:

1. `auto-approve-api.sh` reads `.tool_name` (line 13) and exits unless it is `Bash` (line 17). Grok maps a `Bash` matcher to its own shell tool, so the hook fires, but the event carries Grok's tool name: `tool_name` is `run_terminal_command`. Run with Grok's event shape (`{"hookEventName":"pre_tool_use","hook_event_name":"PreToolUse","toolName":"run_terminal_command","tool_name":"run_terminal_command","toolInput":{"command":"railway status --json"},"tool_input":{"command":"railway status --json"}}`), the script exits 0 with no output.
2. Even with the name fixed, Grok's hooks guide says an `allow` "means only \"not blocked\"" and "does not auto-approve a call the user would otherwise be asked about" (10-hooks.md line 296 in xai-org/grok-build).

So a Grok user gets Grok's normal permission prompt for every `railway` command, which is safe, but the hook's description ("Auto-approve Railway API calls") does not hold there, and the README's Grok section does not say so.

Suggested fix: a short note in the Grok Build section (README.md line 117) that the hook has no effect in Grok, with the native alternative for read-only commands:

```toml
# ~/.grok/config.toml
[permission]
allow = [
  "Bash(railway status *)",
  "Bash(railway whoami *)",
  "Bash(railway logs *)",
  "Bash(railway deployment list *)",
]
```

Grok strips leading environment assignments such as `RAILWAY_CALLER=...` before matching, so these cover the skill's tagged calls. In a clean Grok home these rules load (`4 loaded, 0 skipped`).

While there: the README does not mention that the skill prefixes Railway CLI calls with `RAILWAY_CALLER` and `RAILWAY_AGENT_SESSION` for telemetry (SKILL.md line 131: "Do not run a separate `export` preflight solely for telemetry"), or that `railway-api.sh` sends `X-Railway-Skill-Id`, `X-Railway-Skill-Version` and `X-Railway-Agent-Session` (lines 46 to 48). One sentence would cover it. The helper's default version tag is `1.2.3` (line 8) while the skill is `1.6.1`, so direct calls report the wrong version.
