**Title:** Say what the Unity CLI sends, and cover Grok in the MCP client list

**Body:**

The plugin installs as skills. The README already says the agent can install the Unity CLI and run C# in the open Editor (README.md lines 94 and 124). Three details live in the `unity-cli` skill and not in that README:

1. If `unity` is missing, the skill runs `curl -fsSL https://unity.com/install.sh | bash` (SKILL.md line 67), or `irm https://unity.com/install.ps1 | iex` on Windows (line 72). SECURITY.md line 56 says the script downloads from `public-cdn.cloud.unity3d.com` and checks a SHA-256.
2. The CLI reports anonymous crashes to Sentry unless `UNITY_NO_CRASH_REPORT` is set (SKILL.md line 627).
3. Every `unity` run sends one anonymous `cli telemetry` usage ping even when analytics are opted out, unless `UNITY_NO_CLI_INVOKED_TELEMETRY=1` (SKILL.md line 627, and diagnostics-maintenance.md line 298).

A sentence in "Works best with the Unity CLI" naming the install URL and those two opt-outs would match what the skill already tells the agent.

Two smaller Grok gaps:

- `unity mcp configure` lists 16 clients and not Grok (integration-advanced.md line 86). `unity skill install` already includes `grok` (line 156). Adding `grok` to the configure list, if the CLI can write Grok's MCP config, would match.
- The README's Grok line is `grok plugin install Unity-Technologies/unity-agent-plugin --trust` (line 45), which follows the default branch. A pinned form is `grok plugin install https://github.com/Unity-Technologies/unity-agent-plugin.git@<sha> --trust`.

The Grok Build CLI was not installed on the machine that read this commit, so the install line was not run.
