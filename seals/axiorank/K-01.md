**Title:** Central audit sends raw tool arguments and results; the README says redacted metadata

**Body:**

The Privacy section of the README (line 76 at `08fe4b8`) says: with `AXIORANK_API_KEY` set, "redacted call metadata is sent to your AxioRank workspace", and the guard "redacts secret material before recording anything".

In the vendored `bin/guard.mjs`, `reportCall` posts `arguments: call.arguments` (line 1550) and `reportResult` posts `resultText` (line 1571). Both are the raw values from the hook input. The redacted copy that `inspectContent` builds (`redactedPayload`) is not what gets sent.

Reproduction, with nothing leaving the machine:

1. Start a local HTTP listener on `127.0.0.1:48711` that records request bodies.
2. Run `scripts/guard.sh` with `AXIORANK_API_KEY=test` and `AXIORANK_BASE_URL=http://127.0.0.1:48711`, feeding a `PreToolUse` event whose command is `export DB_PASSWORD=hunter2hunter2 && psql -c "select 1"`, then a `PostToolUse` event for a file read whose result is some private text.
3. The guard denies the command locally as a secret. The listener still receives `{"tool":"agent.run_terminal_command","arguments":{"command":"export DB_PASSWORD=hunter2hunter2 && ..."}}` and `{"phase":"result","resultText":"<the file text>"}`.

Suggested fix: send the redacted payload (or only metadata: tool name, detector categories, risk score) from `reportCall` and `reportResult`, or, if the server is meant to receive full content and redact on its side, say so plainly in the Privacy section.
