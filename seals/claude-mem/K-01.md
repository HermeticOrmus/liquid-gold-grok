**Title:** Under Grok Build the Setup hook never runs, so the plugin's dependencies are never installed and every hook dies on `zod/v3`

**Body:**

Grok Build (grok 1.0.44) loads `plugin/hooks/hooks.json` when the plugin is installed with `grok plugin install "https://github.com/thedotmack/claude-mem.git@<sha>#plugin" --trust`. Its hook events have no `Setup`, and its hooks guide says "Grok skips unrecognized event names" (`docs/user-guide/10-hooks.md` line 162 in xai-org/grok-build). `ensurePluginDependencies` in `plugin/scripts/version-check.js` (line 204) is the only place `bun install --production` runs, so in Grok nothing installs `zod`, `shell-quote` or the tree-sitter grammars.

What we saw at `e290f3d`, running each `hooks.json` command with the JSON Grok sends and `CLAUDE_PLUGIN_ROOT` set as Grok sets it for plugin hooks (scratch `HOME`, no network):

```text
error: Cannot find module 'zod/v3' from '<plugin>/scripts/worker-service.cjs'
claude-mem: hook command failed (exit 1)
```

That came from all eight calls (SessionStart twice, UserPromptSubmit, PreToolUse, PostToolUse twice, Stop, SessionEnd). Each hook then exits 0 through the fail-open wrapper, so Grok records success and the user never learns that nothing is being captured. No database was created.

After `bun install --production` in the installed `plugin/` folder (37 packages, about 40 s), the same sequence started the worker, and the prompt and both tool calls were stored.

This looks like the plan-16 problem in #3604 (a plugin root without its runtime dependencies), reached through a host that never fires `Setup`. Possible fixes:

- When `worker-service.cjs start` (the SessionStart hook) finds the dependency closure incomplete and no Setup marker, run the same `ensurePluginDependencies` before starting the worker. The SessionStart hook has a 60 s timeout and Grok runs it in the foreground, which covered the 40 s install here.
- Or bundle `zod` and `shell-quote` into `worker-service.cjs`, so only the lazily used tree-sitter grammars need an install.
- Either way, let the start step exit non-zero with one clear stderr line when dependencies are missing. Grok fails open on a passive event, but it shows a non-zero exit and the first stderr line in the session scrollback, so the user would see why memory is empty.
