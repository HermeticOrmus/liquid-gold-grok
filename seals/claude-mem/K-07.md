**Title:** Grok Build: document the install path and three defaults that differ from Claude Code

**Body:**

The README documents Claude Code and Grok Bot. Grok Build (xAI's `grok` CLI) also installs Claude Code plugins, and four things trip a Grok Build user at `e290f3d`:

1. **The obvious install gets a different edition.** `grok plugin install thedotmack/claude-mem` reads the repository root, where `.grok-plugin/plugin.json` points at `claude-mem-grok-bot/` (4 skills, a stdio server run as `npx -y claude-mem mcp`, and a remote server at `https://cmem.ai/api/mcp`), with no capture hooks. The edition with hooks installs with `grok plugin install "https://github.com/thedotmack/claude-mem.git#plugin" --trust`. A README line for Grok Build with the `#plugin` form would settle it.
2. **The marketplace route times out.** `grok plugin marketplace add thedotmack/claude-mem` succeeds, then every sync fails with `git clone timed out after 15s`; Grok clones the full history, which is 488 MiB, mostly the slide PDFs under `plans/`. The `#plugin` direct install works, so the README line above covers it.
3. **The observer needs Claude Code.** With the default `CLAUDE_MEM_PROVIDER: 'claude'`, a machine without the `claude` CLI queues every event and never compresses it (worker log: `Skipping Claude generator start until setup is repaired ... Claude executable not found`). A sentence telling non-Claude hosts to set `gemini`, `openrouter` or `openai-compatible`, or to keep Claude Code signed in, would save a confusing empty memory.
4. **The skip list uses Claude tool names.** `CLAUDE_MEM_SKIP_TOOLS` defaults to `ListMcpResourcesTool,SlashCommand,Skill,TodoWrite,AskUserQuestion`; Grok's equivalents are `todo_write` and `ask_user_question`, and in our sandbox run a `todo_write` call was stored and queued for the observer. Adding the Grok names to the default would keep that noise out.

These sit beside #4282, which maps Grok's camelCase hook fields; the install-dependency, context-delivery and MCP-start issues are filed separately.
