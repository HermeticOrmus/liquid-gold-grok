**Title:** docs: SECURITY.md says there is no telemetry; plugin installs never see the consent prompt

**Body:**

SECURITY.md line 157 says "Claude-mem does not collect telemetry." The worker sends anonymous PostHog events by default (`explainTelemetryConsent` returns `{ enabled: true, source: 'default' }` when no decision is recorded, `src/services/telemetry/consent.ts` line 62), and `docs/public/telemetry.mdx` documents that well. The README does not mention telemetry.

The telemetry page also says the default "is never silent for new installs" because `npx claude-mem install` asks once. A plugin installed through a host's plugin manager never runs the installer. We installed the pinned `plugin/` folder through Grok Build, ran its hooks in a sandbox with a local listener standing in for `us.i.posthog.com`, and the worker posted `worker_started` (version, os, kernel release, locale, provider, database counts and size, process memory, random install id) and `worker_stopped`; `telemetry.json` held no decision. With `DO_NOT_TRACK=1`, nothing was sent, so the opt-out works.

Suggested changes:

1. SECURITY.md line 157: replace "Claude-mem does not collect telemetry." with "Claude-mem sends anonymous usage analytics (PostHog) unless you opt out; see docs/public/telemetry.mdx. `DO_NOT_TRACK=1` or `npx claude-mem telemetry disable` turns it off."
2. SECURITY.md line 175: the worker port default is `37700 + (uid % 100)` (`SettingsDefaultsManager.ts` line 350), not 37777.
3. README: one line under System Requirements or Configuration naming the telemetry default and the opt-out.
4. For installs that skipped the installer: when `telemetry.json` has no decision, show the one-time notice from the SessionStart hook as `systemMessage` (Claude Code shows it) and hold events until a decision is recorded, or count that first notice as the "never silent" step.
