**Title:** fix(mcp): pass CLAUDE_PLUGIN_ROOT to mcp-search so Grok Build can start it

**Body:**

The `mcp-search` launcher in `plugin/.mcp.json` resolves the server from `process.env.CLAUDE_PLUGIN_ROOT`, then the working directory, then the Codex and Claude Code caches. Grok Build sets `CLAUDE_PLUGIN_ROOT` for plugin hooks but not for MCP servers; it substitutes `${CLAUDE_PLUGIN_ROOT}` as text inside the MCP config instead (`xai-grok-config/src/mcp_servers.rs` line 157 in xai-org/grok-build). So under Grok the launcher finds nothing.

With grok 1.0.44 in a clean Grok home, after `grok plugin install "https://github.com/thedotmack/claude-mem.git@e290f3d#plugin" --trust`:

```text
grok mcp doctor mcp-search
  server started (0.0s)
  handshake failed (connection closed: initialize response)
```

and the server log reads `claude-mem: mcp server not found`.

Suggested change to `plugin/.mcp.json` (and to the generator that writes it):

```json
"mcp-search": {
  "type": "stdio",
  "command": "node",
  "args": ["-e", "<launcher unchanged>"],
  "env": { "CLAUDE_PLUGIN_ROOT": "${CLAUDE_PLUGIN_ROOT}" }
}
```

We tested exactly this on a local copy of the pinned `plugin/` folder installed into a clean Grok home: `handshake OK (protocol 2025-11-25)`, `15 tools discovered`. Grok substitutes the token inside `env` values, so the launcher's first candidate is correct. In Claude Code the host already sets the variable, so the entry should be a no-op there; please confirm with your Claude Code and Codex launchers.
