**Title:** PRIVACY.md: name the default cross-model review pass and its off switches

**Body:**

`PRIVACY.md` (last changed in #967) still says:

> Data leaves your machine only when your host/tooling or an explicitly invoked integration performs a network request.

> If you do not invoke these integrations, they do not transmit your project data.

That is no longer the whole picture. With `cross_model_review_mode` at its default `auto`, `ce-code-review` sends the reviewed diff, and `ce-doc-review` the full document, to a second provider's agent CLI whenever the adversarial reviewer (or the judgment trio) is selected and a different-family CLI is installed. `ce-code-review/SKILL.md` line 31 makes the skill invocation the authorization, and in `mode:agent`, which `lfg` uses at step 4, the user sees no notice; only the stderr audit line records the send (`references/cross-model-review.md` line 85). The guides describe all of this well (`docs/guides/ce-code-review.md` line 131, `docs/guides/configuration.md` line 98), and #1396 gave it a clean off switch. The privacy page is the one place that has not caught up, and it is the page a security reviewer reads first (#225 is that reader).

I checked the workers at 1fd12d6 in a scratch repository, with a stub `codex` on `PATH` that records each call and sends nothing, and host family `grok`:

```text
# ce-code-review worker, CROSS_MODEL_DRY_RUN=1
RESOLVED_PEERS: codex
# same, CROSS_MODEL_PEERS=none
[cross-model] provider 'codex' not in CROSS_MODEL_PEERS allowlist; skipping
# ce-doc-review worker, route codex, no allowlist
[cross-model-doc] peer run: provider=codex route=codex model=gpt-6-luna (effort xhigh) lens=adversarial read-only least-privilege (idle 480s / attempt hard 1200s); full document content egresses to this provider via this route
(stub called once)
# same, CROSS_MODEL_PEERS=none
(stub not called)
```

The same page also lists "Context7 MCP (`https://mcp.context7.com/mcp`)" among what the plugin includes; the bundled server was removed in #486 (CHANGELOG line 440), and the researcher prompts use Context7 only when the user connects it.

Suggested replacement for the "Optional integrations and tools" section:

```markdown
2. Cross-model review (on by default when a peer CLI is installed)

`ce-code-review` and `ce-doc-review` can run one review lens through a second model provider. When the lens is selected and an agent CLI from a different model family is installed (`codex`, `claude`, `grok`, `cursor-agent`, or `opencode`), the reviewed diff or document is sent to that provider. In interactive runs the skill names the provider before sending; in `mode:agent` runs (for example inside `lfg`) it writes a stderr audit line instead. To keep review content on your host:

- set `cross_model_review_mode: off` in `.compound-engineering/config.local.yaml` or `config.yaml`, or
- set `CROSS_MODEL_PEERS` to the providers you allow (`CROSS_MODEL_PEERS=none` allows none), or
- tell the agent not to use external review for that run.

`ce-pov` consults other models only when you ask for a panel, and `ce-work` uses an external author only when `work_engine_mode` enables it.

3. Optional integrations you invoke

- Proof (`https://www.proofeditor.ai`) when using share/edit flows
- Context7, when you have connected its MCP server or installed its CLI yourself
- Other skills you call by name (`ce-polish` live mode with your OpenAI key, `ce-promote` with Spiral, `ce-sweep` with Slack or GitHub) that call their own services
```
