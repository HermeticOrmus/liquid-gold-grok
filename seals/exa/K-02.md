**Title:** Grok Build: use /mcps, and give a direct install line

**Body:**

Two install details don't match Grok Build at grok 1.0.46.

1. **Sign-in command.** README step 5 (line 29) and `commands/tutorial.md` step 1 (line 11) say to open `/mcp`, select **exa**, and press `i`. The user guide Grok writes into a fresh home lists `/mcps` (docs/user-guide/04-slash-commands.md, heading at line 359) and `/marketplace` (line 232). There is no `/mcp` heading. `/marketplace` in step 3 is the right command.

2. **Install without a marketplace already registered.** Steps 3 and 4 say to open `/marketplace` and find **exa**. In a clean Grok home, where no marketplace is configured, `grok plugin install exa --trust` exits 1 with `No marketplace plugin named "exa" in any registered marketplace`. The form that installs this commit is:

```bash
grok plugin install https://github.com/exa-labs/exa-grok-plugin.git@879fae0c814765c43f39ea8f56aae1d44e9d9bc8 --trust
```

That printed `Installed 1 plugin(s) from https://github.com/exa-labs/exa-grok-plugin.git@879fae0c814765c43f39ea8f56aae1d44e9d9bc8: exa`. xAI's catalog also lists the plugin, so `/marketplace` works once that catalog is registered. A direct line covers the home that has neither.

3. **Command name.** `commands/tutorial.md` loads as `/tutorial` (`grok inspect` reports the name `tutorial`). A name such as `exa-tutorial` would not collide with another plugin's tutorial.

Suggested change: `/mcps` in the README and the tutorial, the pinned install line next to the marketplace steps, and renaming `commands/tutorial.md` to `commands/exa-tutorial.md`.
