**Title:** firecrawl-interact: ask before submitting forms, logging in or buying

**Body:**

`skills/firecrawl-interact/SKILL.md` triggers on "log in to", "sign in", "submit", "fill out the form" and "multi-step checkout or wizard flows" (line 4), and its examples type an email and click login in Firecrawl's hosted browser (lines 35, 36 and 65). The skill has no step that stops before an action with effects outside the session. The hosted server's own description of `firecrawl_interact` says: "This acts on the live site, so actions such as form submission can create persistent external side effects."

The monitor skill already writes goals from the user's own words and notes that external email recipients must confirm before they get alerts, and the Alexandria skill treats accepting provider terms as a legal act that needs the user's explicit authorization. The same rule fits here.

Proposed addition, under "When to use":

```markdown
- Before any action that submits data, logs in, accepts terms, sends a message or makes a purchase, tell the user what will be submitted and to which site, and wait for a yes. Never type credentials the user has not given for this task, and prefer a `--profile` the user logged into themselves.
```
