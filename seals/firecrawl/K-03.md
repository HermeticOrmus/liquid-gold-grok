**Title:** firecrawl-parse: say that the file is uploaded to Firecrawl, and trigger only on Firecrawl parsing

**Body:**

`skills/firecrawl-parse/SKILL.md` describes parsing as "a **local-filesystem** operation" that runs through the CLI "rather than the bundled (hosted) Firecrawl MCP, which cannot access local files" (line 14), and the README says the one thing the hosted server "can't provide is parsing files on your local disk" (line 35). Both paths in fact send the whole file to Firecrawl:

- The CLI the skill pins, `firecrawl-cli@1.16.2`, reads the file and posts it to `https://api.firecrawl.dev/v2/parse` (`src/commands/parse.ts`, line 4: "Uploads a local file to the Firecrawl /v2/parse endpoint"; line 182: the `fetch` POST).
- The hosted server offers `firecrawl_parse` to every session, keyless ones included, and its description reads: "Hosted MCP uses two calls: first provide `filePath` to receive upload instructions, upload locally, then call again with the returned `uploadRef`".

The skill's description (line 4) claims phrases such as "read this file" and any request where "a local file path (not a URL) is provided", for HTML as well as PDF and Office files. A user who asks Grok to read a local document can have it uploaded without being told; the only hint is "Max upload size: 50 MB per file" (line 58).

Proposed change:

1. Replace the "MCP note" with one sentence that says where the file goes: "Parsing uploads the file to Firecrawl's API (through the CLI or the hosted `firecrawl_parse` tool) and returns markdown."
2. Narrow the description to requests to parse or convert a document with Firecrawl, and drop "read this file" and the bare local-path trigger, so ordinary file reads stay local.
3. In the README, change line 35 to say that parse uploads local files, and list it with the other network operations.
