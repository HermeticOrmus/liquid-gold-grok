**Title:** Grok connects keyless and never signs in, so most of the plugin's tools are missing

**Body:**

The README says that installing the plugin "wires up the MCP automatically", that "the first web action signs you in through your browser" (line 5), and that "the bundled MCP covers the full remote toolset (scrape, search, find_tools, crawl, map, extract, agent, interact, monitor)" (line 35). The `.mcp.json` note says the same.

With grok 1.0.44 in a clean Grok home, after `grok plugin install https://github.com/firecrawl/firecrawl-grok-plugin.git@fc26fcf97921f5b4db93b06e000b6366e8d67c48 --trust`, on 2026-10-01:

```text
firecrawl (http: https://mcp.firecrawl.dev/v2/mcp)
  server started (0.3s)
  handshake OK (protocol 2025-11-25)
  3 tools discovered
```

The server accepts the session without credentials, and its `initialize` instructions explain the count: "Hosted keyless sessions expose firecrawl_search, firecrawl_scrape, and firecrawl_parse with usage limits. ... An Authorization bearer API key can provide higher usage limits and expose additional tools". Because the session succeeds anonymously, Grok has no reason to start OAuth, and `/.well-known/oauth-protected-resource` on `mcp.firecrawl.dev` returns 404, so there is no OAuth metadata to find. PR #1 recorded a `401` challenge when `.mcp.json` was added, so this looks like a server change the plugin has not caught up with.

The result for a Grok user: the map, crawl, agent, interact, monitor and Alexandria skills send the agent to tools that are not in the session, and the CLI fallback is not installed by default.

What works: a server entry in `~/.grok/config.toml` with the same name replaces the plugin's, and a bearer header brings the list to 27 tools:

```toml
[mcp_servers.firecrawl]
url = "https://mcp.firecrawl.dev/v2/mcp"
headers = { "Authorization" = "Bearer ${FIRECRAWL_API_KEY}" }
```

Suggested fix, any of:

1. In the README, replace the sign-in section with the two real modes: keyless (search, scrape, parse) and API key (everything), with the config above for Grok.
2. Have keyless sessions tell the agent how to unlock the rest, so the skills can say it instead of failing.
3. If OAuth is still meant to work, serve the protected-resource metadata and challenge clients that are not eligible for keyless use.
