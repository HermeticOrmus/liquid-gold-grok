**Title:** CLI skill documents --sourcePath before the pinned npm release has it

**Body:**

At `b2f522c` the CLI skill tells an agent to evaluate a local file:

```bash
chrome-devtools evaluate_script --pageId 1 --sourcePath /path/to/script.js --format script
```

That line is [skills/chrome-devtools-cli/SKILL.md:137](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/b2f522c8ba0fd2e00a679159b4aa5243de5f1b78/skills/chrome-devtools-cli/SKILL.md#L137). The same commit's configuration guide documents `--file-navigations` ([docs/configuration.md:212](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/b2f522c8ba0fd2e00a679159b4aa5243de5f1b78/docs/configuration.md#L212)).

`mcp.json` and `.claude-plugin/plugin.json` still start `chrome-devtools-mcp@1.10.1`. npm reports that version published `2026-09-23T10:42:53.202Z`. Tag `chrome-devtools-mcp-v1.10.1` has neither flag:

```text
$ git grep -e sourcePath -e fileNavigations chrome-devtools-mcp-v1.10.1 -- skills src docs
(exit 1, no matches)
```

`--sourcePath` is commit 9cf47a4 (2026-10-01, #2606). `--file-navigations` is commit 54cae57 (2026-10-01, #2853). An agent that follows the new skill line against the package this commit pins will not find the flag. The inline `evaluate_script` examples on the two lines above still match 1.10.1.

Proposed change: drop the `--sourcePath` example until the release that contains 9cf47a4, and bump the version in `mcp.json` and `.claude-plugin/plugin.json` in that same release. Or keep the example and say it needs a build of this commit, not `@1.10.1`.
