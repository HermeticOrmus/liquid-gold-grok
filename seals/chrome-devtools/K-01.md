**Title:** Add .mcp.json so Grok Build registers the plugin's MCP server

**Body:**

xAI's official Grok marketplace lists this repository as the `chrome-devtools` plugin. With grok 1.0.44 in a clean Grok home at `02c0112`:

```text
$ grok plugin install https://github.com/ChromeDevTools/chrome-devtools-mcp.git@02c0112cd57e4fa4bac31a1e69d7507601773b14 --trust
Installed 1 plugin(s) from ...: chrome-devtools
$ grok plugin details chrome-devtools
    chrome-devtools v1.10.1
  components: 1 skill dir(s), 0 command dir(s), 0 agent dir(s)
```

The seven skills load, but no MCP server does. For comparison, `cloudflare/skills`, which ships a `.mcp.json`, reports `components: ... MCP servers` in the same home.

Grok reads the root `plugin.json` here, which has no `mcpServers`, and looks for servers in `.mcp.json`. This repository declares the server inline in `.claude-plugin/plugin.json` and in `mcp.json` (agent-plugins schema, no leading dot), so Grok users get skills that call Chrome DevTools MCP tools with no server behind them.

Proposed change:

1. Add `.mcp.json` at the root with the same server as `mcp.json`:

   ```json
   {
     "mcpServers": {
       "chrome-devtools": {
         "type": "stdio",
         "command": "npx",
         "args": ["--prefix", "${PLUGIN_DATA}", "chrome-devtools-mcp@1.10.1"]
       }
     }
   }
   ```

   Whether Grok expands `${PLUGIN_DATA}` the way other agents do is worth a check in a Grok session; `["-y", "chrome-devtools-mcp@1.10.1"]` is the conservative form. If the release tooling bumps the version in `mcp.json`, it would need to bump this file too.

2. In `docs/client-configurations.md` (Grok Build section, line 295), mention the marketplace plugin, and pin the version in the manual line: `grok mcp add chrome-devtools -- npx -y chrome-devtools-mcp@<version>` rather than `@latest`.

3. Optional: the two manifests name the plugin differently (`chrome-devtools-mcp` in `.claude-plugin/plugin.json`, `chrome-devtools` in `plugin.json`). Grok uses the second, so `grok plugin details chrome-devtools-mcp` reports not found. One name in both would remove the confusion.

Until then, the workaround for Grok users is `grok mcp add chrome-devtools -- npx -y chrome-devtools-mcp@1.10.1`, which registers the server (checked with `grok mcp list`).
