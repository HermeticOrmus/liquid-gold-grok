**Title:** Add .mcp.json so Grok Build registers the plugin's MCP server

**Body:**

xAI's official Grok marketplace lists this repository as the `chrome-devtools` plugin. With grok 1.0.46 in a clean Grok home at `b2f522c`:

```text
$ grok plugin install https://github.com/ChromeDevTools/chrome-devtools-mcp.git@b2f522c8ba0fd2e00a679159b4aa5243de5f1b78 --trust
Installed 1 plugin(s) from ...: chrome-devtools
$ grok plugin details chrome-devtools
    chrome-devtools v1.10.1
  components: 1 skill dir(s), 0 command dir(s), 0 agent dir(s)
$ grok inspect --json
```

The seven skills load, but no plugin MCP server does. `grok inspect --json`, run from an empty folder, lists those seven skills and zero MCP servers whose source is this plugin.

Grok reads the root `plugin.json` here, which has no `mcpServers`, and looks for servers in `.mcp.json`. This repository declares the server inline in `.claude-plugin/plugin.json` and in `mcp.json` (agent-plugins schema, no leading dot), so Grok users get skills that call Chrome DevTools MCP tools with no server behind them. A `.mcp.json` removed in #2095 is not a duplicate of `mcp.json` for Grok: Grok does not read the undotted file.

Proposed change:

1. Add `.mcp.json` at the root with the same server as `mcp.json`:

   ```json
   {
     "mcpServers": {
       "chrome-devtools": {
         "type": "stdio",
         "command": "npx",
         "args": ["--prefix", "${PLUGIN_DATA}", "chrome-devtools-mcp@1.10.1"]
       }
     }
   }
   ```

   Whether Grok expands `${PLUGIN_DATA}` the way other agents do is worth a check in a Grok session; `["-y", "chrome-devtools-mcp@1.10.1"]` is the conservative form. If the release tooling bumps the version in `mcp.json`, it would need to bump this file too.

2. In `docs/client-configurations.md` (Grok Build section, line 295), mention the marketplace plugin, and pin the version in the manual line: `grok mcp add chrome-devtools -- npx -y chrome-devtools-mcp@<version>` rather than `@latest`. On grok 1.0.46 the current line does register a server (`npx chrome-devtools-mcp@latest`); it is unpinned, and it does not install the plugin.

3. Optional: the two manifests name the plugin differently (`chrome-devtools-mcp` in `.claude-plugin/plugin.json`, `chrome-devtools` in `plugin.json`). Grok uses the second, so `grok plugin details chrome-devtools-mcp` reports `Plugin "chrome-devtools-mcp" not found`. One name in both would remove the confusion.

Until then, the workaround for Grok users is `grok mcp add chrome-devtools -- npx -y chrome-devtools-mcp@1.10.1`, which registers the server (checked with `grok mcp list` on grok 1.0.46). The server was not started.
