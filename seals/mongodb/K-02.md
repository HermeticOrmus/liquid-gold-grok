**Title:** Grok Build: install section for the mongodb plugin, and harness-neutral tool names

**Body:**

The `mongodb` plugin works in Grok Build as it is. With grok 1.0.44 in a clean Grok home, the plugin at this commit installs, its 7 skills load, and `grok mcp doctor mongodb` reports `handshake OK` and `31 tools discovered`. xAI's Grok marketplace lists it too. Two small things would help Grok users.

**1. Install section.** `README.community.md` covers Claude, Cursor, Codex, Gemini and Copilot CLI (from line 7), and the Grok section in `README.md` (line 63) covers `mongodb-atlas` only. In a Grok home without xAI's marketplace, `grok plugin install mongodb --trust` gives `No marketplace plugin named "mongodb" in any registered marketplace`. This repository's own Grok marketplace file works:

```bash
grok plugin marketplace add mongodb/agent-skills
grok plugin install mongodb@agent-skills --trust
```

(checked: `Installed 1 plugin(s) from agent-skills: mongodb`). Note that Grok registers the marketplace under the repository name, `agent-skills`, not the `mongodb-plugins` name in `.grok-plugin/marketplace.json`. A `### Grok` section with those two lines, or with `/marketplace` as in `README.md`, would cover it. Credentials work in Grok the way the setup skill describes for shell-based clients: Grok passes the environment it was started with to the server.

**2. Tool names.** `mongodb-natural-language-querying` (lines 19 to 38) and `mongodb-schema-design` (lines 148 to 150) write tools as `mcp__mongodb__find`, `mcp__mongodb__collection-schema` and so on, which is Claude Code's naming. In Grok the same tool is `mongodb__find`, and its `use_tool` takes that qualified key. `mongodb-query-optimizer` already uses the plain server names (`collection-indexes`, `explain`, `find`), which every client can map. Using that style in the other two skills would make them read the same everywhere. `allowed-tools: mcp__mongodb__*` can stay: Grok accepts that spelling in permission rules.
