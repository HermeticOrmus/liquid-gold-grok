**Title:** mongodb plugin: say what the MCP server sends to MongoDB, and fix the configuration link

**Body:**

The `mongodb` plugin starts `mongodb-mcp-server@<3` through `npx` (`plugins/mongodb/mcp.json`), which resolved to 2.1.2 on 2026-10-01. At that version the server:

- sends usage telemetry to MongoDB by default (`MDB_MCP_TELEMETRY` defaults to `"enabled"`, server README line 466; "the MCP server will collect usage data and send it to MongoDB", line 588), and
- sends `search-knowledge` queries to `https://knowledge.mongodb.com/api/v1/` (line 430).

Both are documented by the server, with opt-outs (`MDB_MCP_TELEMETRY=disabled`, `DO_NOT_TRACK=1`). The plugin's own README (`plugins/mongodb/README.md`) and the setup guide (`README.community.md`) do not mention either, and the guide's pointer to "a full list of configuration options" (`README.community.md` line 69) goes to `https://www.mongodb.com/docs/mcp-server/configuration/options/`, which returns 404. The live page with the telemetry opt-out is `https://www.mongodb.com/docs/mcp-server/local-mcp/configuration/enable-or-disable-features`.

Proposed change:

1. A short paragraph in `plugins/mongodb/README.md` and `README.community.md`: the server sends usage telemetry to MongoDB unless `MDB_MCP_TELEMETRY=disabled` or `DO_NOT_TRACK=1` is set, and `search-knowledge` queries MongoDB's knowledge service.
2. Point the configuration link at a page that exists.
3. In `mongodb-mcp-setup`, next to the read-only question in Step 4, offer the telemetry opt-out the same way.

Checked with grok 1.0.44: Grok passes the shell environment to the plugin's server (with `MDB_MCP_READ_ONLY=true` exported, `grok mcp doctor mongodb` lists 20 tools instead of 31), so the opt-out works for Grok users as an exported variable.
