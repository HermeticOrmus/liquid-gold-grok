**Title:** keep API tokens out of curl's argument list

**Body:**

`skills/sre/SKILL.md` line 26 tells the agent to use `scripts/curl-auth` so tokens stay in environment variables and do not appear in the command. `scripts/config` already refuses to print secrets when stdout is a terminal. `curl-auth` then expands the token into curl's arguments. For the axiom tool that is line 135:

```bash
curl "${CURL_ARGS[@]}" \
    -H "Authorization: Bearer $AXIOM_TOKEN" \
    -H "X-Axiom-Org-Id: $AXIOM_ORG_ID" \
    ...
```

The Grafana, Pyroscope, Sentry and Slack branches do the same with their tokens, and so does `skills/axiom-alerting/scripts/axiom-api` line 54. The command the agent types (`scripts/curl-auth axiom prod <url>`) does not contain the token, and a normal curl does not print the header. The value is still visible to anything that can read the process arguments for the duration of the request.

Run at that commit with a stand-in `curl` earlier on `PATH` and a token `xaat-secret-token-value` in `~/.config/axiom-sre/config.toml`: argument 9 was `Authorization: Bearer xaat-secret-token-value`. The alerting client, with `xaat-home-token` in `~/.axiom.toml`, built the same header.

One way to keep the header out of the argument list is a mode-600 file passed to `curl --config`, removed when curl returns. The file holds `header = "Authorization: Bearer ..."` and is not an argument. The same pattern covers the org id header and the other tools' tokens.
