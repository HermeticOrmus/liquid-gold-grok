**Title:** fix stale axiom-api headers

**Body:**

Three comments in the API clients are left over from an older layout, and the user agent still says 1.0 at release 1.1.0.

1. `skills/query-metrics/scripts/axiom-api` line 6, `skills/building-dashboards/scripts/axiom-api` line 9, and `skills/building-dashboards/scripts/metrics/axiom-api` line 9 say credentials come from `~/.axiom.toml` "shared with axiom-sre". The SRE skill reads `~/.config/axiom-sre/config.toml`. The repository README line 103 says the two files are separate, and `skills/query-metrics/README.md` says the same. The setup comments in `query-metrics` and `building-dashboards` (`scripts/setup` line 7) repeat the "shared with axiom-sre" line.

2. `skills/building-dashboards/scripts/axiom-api` line 4 says the script rewrites `api.*` to `app.*/api`. The code sets `API_URL` to `${url}/v2` and does not rewrite the host. On 2026-10-04, `GET https://api.axiom.co/v2/dashboards` returned 401 `auth token not provided` (the route exists), and `GET https://app.axiom.co/api/dashboards` returned 406 `Only HTML requests are supported here`. The comment describes a host the script does not call.

3. Those clients send `User-Agent: axiom-skills/1.0 (agent)` (`query-metrics` line 64, dashboard client line 83, metrics client line 67). `version.txt` and the manifests are 1.1.0.

Suggested fix: say the file is `~/.axiom.toml` and that SRE uses a different file; delete the rewrite warning; set the user agent from `version.txt` or drop the version from it.
