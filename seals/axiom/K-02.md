**Title:** axiom-alerting: the API token is read from ~/.axiom.toml only

**Body:**

`skills/axiom-alerting/SKILL.md` line 12 says the bearer token comes from `.axiom.toml` in the project root or in the home directory. `scripts/axiom-api` sets `CONFIG_FILE="$HOME/.axiom.toml"` and never looks at the project file (line 14). The skill README (line 15) and the repository README already tell people to use `~/.axiom.toml`.

Run at that commit, with a project `.axiom.toml` and no home file:

```
Error: <home>/.axiom.toml not found
```

exit 1. With the same deployment written to `$HOME/.axiom.toml`, the script got past that check and built a request to `https://api.axiom.co/v2/monitors`.

The small fix is to make the skill sentence match the script and the README: the token is read from `~/.axiom.toml` only. If the project-root path was intentional, the script should try `./.axiom.toml` and then the home file, and the README should say so too.
