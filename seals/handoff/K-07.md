**Title:** fix(handoff): reach the command from the skill by a path Grok fills in

**Body:**

1. **K-07.** `plugins/handoff/skills/handoff-patterns/SKILL.md` line 11 says: follow the procedure in `${CLAUDE_PLUGIN_ROOT}/commands/handoff.md`. Grok Build 1.0.44 fills `$ARGUMENTS`, `${SKILL_DIR}`, `${CLAUDE_SKILL_DIR}`, `${SESSION_ID}` and `${CLAUDE_SESSION_ID}` in skill text, and names `CLAUDE_PLUGIN_ROOT` only for hooks. If Grok leaves the variable as written, the model gets a path it cannot open and writes a handoff without the index and clipboard steps.

   Change line 11 to:

   > To write a handoff, follow the procedure in `${CLAUDE_SKILL_DIR}/../../commands/handoff.md` (the same steps `/handoff` runs) ...

   `${CLAUDE_SKILL_DIR}` is the skill's own folder (`plugins/handoff/skills/handoff-patterns`), so `../../commands/handoff.md` is the command file in both Claude Code and Grok. Confirm in one Grok session that the skill opens the file before merging; the grok placeholder list is read from the binary, not from a session.

2. **K-08.** The index defaults to `~/.claude/sessionflow` (commands/handoff.md lines 36 and 109, README line 11), a Claude Code folder, for Grok users too. Add to the plugin README, after the index sentence:

   > Set `SESSIONFLOW_HOME` to keep the index somewhere else, for example when you use Grok Build and not Claude Code.
