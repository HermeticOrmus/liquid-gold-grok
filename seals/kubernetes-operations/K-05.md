**Title:** fix(kubernetes-operations): pipe JSON into jq in the /k8s scale snippet

**Body:**

v1.0.0 fixed an invalid `jq` expression in the `/k8s` debug snippets. The same kind of crack is left in the `scale` snippets: `plugins/kubernetes-operations/commands/k8s.md` lines 147 and 148 pipe YAML into jq, which only parses JSON.

```bash
kubectl get vpa -n production -o yaml | \
  jq '.items[].status.recommendation.containerRecommendations[]'
```

With jq 1.8.2, YAML input of that shape fails before the filter runs:

```text
jq: parse error: Invalid numeric literal at line 1, column 11
```

The same filter on JSON input prints the container recommendations.

Changes:

1. K-05: `kubectl get vpa -n production -o json | jq '.items[].status.recommendation.containerRecommendations[]'`.
2. K-06: line 151 uses `kubectl drain node-1 --ignore-daemonsets --dry-run=true`. kubectl still accepts the boolean form but warns that it is deprecated and maps it to `client` (`pkg/cmd/util/helpers.go`, `GetDryRunStrategy`, in kubernetes/kubectl at `d1f17c3`). Use `--dry-run=client`, as line 120 already does.
3. K-07: the plugin README promises operator patterns ("CRDs, controller loops, when to write vs use existing operators") and ingress coverage for "nginx, Traefik, gateway-api, TLS, rate limiting" (README.md lines 17 and 18). The agent, command and skills have one RBAC row about operators and no material on controller loops, Traefik, Gateway API or rate limiting. Either add that material or trim the two bullets to what ships.
4. K-08: README.md line 9 lists one skill; the plugin ships two (`kubernetes-operations` and `k8s-patterns`).
