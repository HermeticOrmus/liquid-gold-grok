**Title:** fix(multiplayer-networking): correct the prediction tick and the server check

**Body:**

Checked on Godot 4.7.stable, headless, including one process running a server and a client over ENet.

1. **Prediction tick (K-02).** `skills/multiplayer-networking/SKILL.md` line 246 sets `input.tick = multiplayer.get_remote_sender_id()  # Use tick counter`. That call returns the peer ID of the RPC being executed and 0 anywhere else (three calls outside any RPC returned `[0, 0, 0]`), so every input carries tick 0 and `_receive_server_correction` cannot match a correction to its input. Use the physics frame counter:

   ```gdscript
   input.tick = Engine.get_physics_frames()
   ```

   It returned `[1, 2, 3, 4]` over four physics frames.

2. **Server check (K-03).** Lines 192 to 193 give the character's physics to its authority, so the owning client is the authority. `request_attack` (lines 206 to 212) then returns early unless `is_multiplayer_authority()`, with the comment "Only server processes this". In the two-peer test the server printed that it returned early, the client passed the guard, and an `"authority"` `_apply_damage` RPC sent by the client with its own amount was applied on the server. That is the "Trusting damage values from client" anti-pattern at line 405. Guard with the server check and let damage come only from the server; `_apply_damage` must stop being an `"authority"` RPC, because the server's call is refused on the client (`RPC '_apply_damage' is not allowed on node ... from: 1. Mode is "authority"`):

   ```gdscript
   @rpc("any_peer", "call_local", "reliable")
   func request_attack(target_id: int) -> void:
       if not multiplayer.is_server():
           return  # Only the server validates and applies damage
       var target := get_node_or_null("/root/Game/Players/%d" % target_id)
       if target and _is_valid_target(target):
           _apply_damage.rpc(target_id, 10.0)

   @rpc("any_peer", "call_local", "reliable")
   func _apply_damage(target_id: int, amount: float) -> void:
       if multiplayer.get_remote_sender_id() != 1 and not multiplayer.is_server():
           return  # Ignore damage that did not come from the server
       if multiplayer.get_unique_id() == target_id:
           health -= amount
   ```

   and say in a comment that clients call `request_attack.rpc_id(1, target_id)`.

3. **Transfer mode (K-04).** `commands/multiplayer.md` line 300 says `unreliable_ordered` is "Latest delivery guaranteed, older dropped". Godot's class reference for `TRANSFER_MODE_UNRELIABLE_ORDERED`: "Packets are not acknowledged, no resend attempts are made for lost packets. Packets are received in the order they were sent in." Use those terms.

4. **README scope (K-05).** `plugins/multiplayer-networking/README.md` line 32 lists "skill-based, latency-based, party-based matching algorithms" and line 46 lists Unreal replication graph coverage; the plugin carries no matching algorithm and one line on Unreal, and line 53 says the agent does not write the matchmaking backend. Point line 32 at the repository's `docs/06-networking-multiplayer/matchmaking-systems.md`, which does cover ELO-based matching, and mark Unreal as "named, not covered in depth".

5. **Cross-references (K-06).** SKILL.md lines 409 to 411 point at `docs/09-advanced-patterns/` for replication graph patterns (no file under `docs/` mentions a replication graph) and at `docs/12-deployment-distribution/` for matchmaking (it lives in `docs/06-networking-multiplayer/matchmaking-systems.md`). The paths are also relative to the repository root, which an installed plugin does not share with your project. Link the pages by their GitHub URLs and drop the replication graph pointer until that page exists.
